# docintel

Table structure extraction from document images, measured honestly on PubTabNet. There's also a small form key-value linking module tested on FUNSD.

```
table image ──► Table Transformer (TATR v1.1, CPU) ──► rows / columns / header / spanning-cell boxes
                                                           │
                        text boxes (dataset or Tesseract) ─┤  grid + span resolution + text assignment
                                                           ▼
                                                  HTML  /  CSV  /  JSON
```

## What it does

- **`docintel extract table.png --html|--csv|--json`** takes a cropped table image and returns its
  structure: rows, columns, which rows form the header, and cells spanning several rows or columns. Cell
  text comes from a `--words` JSON file you pass in, or from Tesseract if it is installed. With
  neither, you get an empty-celled structure only.
- **`docintel eval --n 300`** scores the pipeline on a fixed-seed sample of PubTabNet validation tables. It reports
  **TEDS** and **TEDS-Struct** with 95% bootstrap confidence intervals, alongside two non-learned baselines,
  results per table category, and counts of each failure type. Post-processing thresholds are chosen on a
  *separate* calibration sample and never on the reported sample.
- **`docintel eval-forms`** handles FUNSD question→answer linking when the gold entities are given (see scope below).
- **`docintel report`** rebuilds the results section of this README from `results/*.json`. CI runs
  `docintel report --check`, so the README cannot drift from the committed numbers.

Example, using a PubTabNet validation image (CDLA-Permissive; imgid 613565) that ships in `examples/` and
Tesseract for the text:

```console
$ uv run docintel extract examples/PMC1064865_002_00.png --csv
,,Age (years),,
Subjects,Number (male/female),Mean + SD,Range,Radiographic grade*
With OA,17 (9/8),64.77 + 9.02,45-83,8
With RA,14 (2/12),60.55 + 12.06,35-74,8
Controls,20 (11/9),37.25 + 7.59,29-59,Normal
```

(Tesseract reads `±` as `+`. The HTML output keeps `Age (years)` as `colspan="2"`.)

### Findings

- TATR with this post-processing beats both non-learned baselines by a wide margin on the same tables
  (paired ΔTEDS-Struct CIs above exclude 0).
- **Spanning cells cause most failures.** Tables with spans score about 0.88 TEDS-Struct, against about 0.97 without them.
  Most failing tables have a spanning cell, and the most frequent error tag is a wrong span count.
- **The borderless category tells us nothing on PubTabNet.** Almost every sampled table has no vertical rules
  (booktabs style), so the "has vertical rules" group is tiny and its CI is wide. A real borderless-vs-ruled comparison needs a
  different dataset.
- Calibration gave only a small gain over TATR's defaults (see the ablation, which uses the calibration sample only).
  Most of the gain comes from undoing the PubTables-1M header-span convention.

### Reading the numbers

- **Text is oracle.** In the PubTabNet eval, cell text comes from the dataset's own per-cell text boxes, not
  from OCR. So full TEDS measures structure plus assigning the right text to the right cell. It does
  **not** measure OCR quality. Published end-to-end TEDS numbers that include OCR are not directly
  comparable.
- **TEDS-Struct is the main metric.** It ignores cell content and is the fair comparison across systems.
- **The two baselines have no header and no spanning-cell logic.** A table with no spans and a one-row header
  loses a little for the missing `<thead>` even when the grid is perfect. The text-box clustering baseline
  also uses the oracle text boxes, which makes it a strong baseline on simple tables.
- **Convention mismatch.** TATR was trained on PubTables-1M, which "canonicalizes" headers by merging blank
  header cells into row-spanning cells. PubTabNet does not do this. The `split_header_rowspans` option undoes
  it, and it was chosen on the calibration sample (see the ablation above).
- **Possible overlap.** Both PubTables-1M and PubTabNet come from PubMed Central Open Access, so some
  source articles may appear in both TATR's training data and PubTabNet validation. I did not check
  for overlap.

## Method

1. **Detection.** `microsoft/table-transformer-structure-recognition-v1.1-all` (DETR with a ResNet-18
   backbone, ~115 MB) runs on CPU. The longest image side is resized to 1000 px, following the TATR reference
   inference. The model outputs boxes for `table row`, `table column`, `table column header` and
   `table spanning cell`.
2. **Post-processing** (`structure.py`, no torch). Detections are filtered by score. Near-duplicate rows and
   columns (more than 50% 1-D overlap) are removed. Rows are stretched to the table's full width and columns to its full height.
   Header rows are the contiguous top rows covered by the header box. Each spanning box claims the
   rows and columns it covers by at least 50%, unless it would cross the header/body boundary or overlap an
   earlier span.
3. **Text assignment.** Each text box goes to the row and column it overlaps most, or to the nearest one if
   it overlaps none. A cell's text is its boxes in reading order.
4. **Calibration.** 24 post-processing configs (row/column threshold × span threshold × header-span
   splitting) are scored on a disjoint, fixed-seed sample of 100 validation tables. The config with the best mean
   TEDS-Struct is frozen before the eval sample is scored.
5. **TEDS** (`teds.py`) follows Zhong et al. 2020: APTED tree edit distance over the `<table>`
   tree. Insert and delete cost 1. A rename costs 1 when tag, colspan or rowspan differ; otherwise it costs the
   normalised Levenshtein distance between cell contents, or 0 for TEDS-Struct. One deliberate difference from the
   official scorer: inline formatting tags (`<b>`, `<i>`, `<sup>`) are stripped from both sides before
   comparing content. Unit tests check hand-computed values (for example, one missing cell out of 4 nodes gives 0.75).
6. **CIs.** Percentile bootstrap with 10,000 resamples over tables. Paired differences resample the same tables for both systems.
7. **Categories.** "Borderless" means no vertical ruling line was found in the image (no pixel column is at least 60%
   ink). "Large" means at least 20 rows. Spans and header rows come from the ground-truth structure tokens.

### Form key-value linking: scope

FUNSD annotates entities (question / answer / header / other) and the links between them. This module takes
the **gold entities and labels as given** and predicts only which question each answer belongs to. The rule:
pick the nearest question on the same line to the left, or directly above with a weighted penalty. The two
parameters are tuned on the FUNSD train split and reported on the test split. The baseline links each answer to the question
whose centre is nearest. Because detecting and labelling entities from raw OCR is not done here, the F1 is for the
linking step only. It is not comparable to published end-to-end relation-extraction numbers, which use
different protocols.

## Running it

```bash
uv sync --all-extras                 # core + torch/transformers/timm + pyarrow/hf-hub + pytesseract
export HF_HUB_DOWNLOAD_TIMEOUT=60

uv run docintel extract table.png --html            # Tesseract text if available, else structure only
uv run docintel extract table.png --csv --words words.json   # [{"text": "...", "bbox": [x1,y1,x2,y2]}, ...]
uv run docintel eval --n 300         # downloads the 230 MB parquet on first run; ~10 min on an 8-core laptop CPU
uv run docintel eval-forms           # downloads FUNSD (17 MB); a few seconds
uv run docintel report               # rewrite the README results block
```

Extras: `model` (torch, torchvision, transformers<5, timm), `data` (pyarrow, huggingface-hub), and
`ocr` (pytesseract; needs the `tesseract` binary). transformers is pinned below 5 because transformers 5.x
fails to load this checkpoint's config (`dilation: None` fails strict validation).

### Development

```bash
uv sync                              # core + dev only; this is what CI installs (no torch, no downloads)
uv run ruff check . && uv run ruff format --check . && uv run mypy
uv run pytest --cov-fail-under=75
```

Tests use a synthetic 3×3 table drawn with PIL, a stub model that returns hand-made detections, a
6-row parquet file written at test time, and a 2-form FUNSD tree. They make no network calls. `tatr.py` (the ~60-line
torch wrapper) is excluded from coverage. Everything downstream of it is tested through the stub.

## Limits

- The input must be a **cropped table**. There is no table detection on full pages.
- Evaluation covers PubTabNet only (scientific tables, mostly booktabs-style). FinTabNet-style financial tables and scanned or
  photographed tables are not evaluated.
- n = 300, so the CIs are a few points wide. Category rows with small n are wider still.
- Tesseract in `extract` is a convenience fallback. It is not evaluated here.
- The FUNSD numbers assume perfect entities.
